## Instructions for Claude Code

**Context:** We have a JSON file of numbered game-book pages (French, choose-your-own-adventure style). Each page has narrative `text` and a `numbers` array listing the page numbers it can branch to. In a single process we need to (A) extract per-choice gains/losses and (B) detect and structure combat encounters, writing everything into one enriched file.

**Task:** Do NOT write a standalone script for me to run — directly process the input file and produce the output file described below. Write and run the transformation yourself, iterating and self-checking extraction quality as you go.

### Input
`work/pretre_jean_forteresse_alamuth.json`, shaped like:
```json
{
  "39": {
    "text": ["..."],
    "numbers": ["95", "448"],
    "file_path": "raw_data/.../xxx.html"
  }
}
```

### Output
`work/pages.json` — a single file containing every page, enriched with `choices` and (where applicable) `fight`:
```json
{
  "page": "39",
  "language": "fr",
  "text": ["..."],
  "file_path": "...",
  "choices": [
    {
      "goto": "95",
      "gains": [
        {"element": "meal", "label_fr": "repas", "amount": 1},
        {"element": "lodging", "label_fr": "nuitée", "amount": 1}
      ],
      "losses": [
        {"element": "gold coin", "label_fr": "pièce d'or", "amount": 5}
      ]
    }
  ],
  "fight": {
    "fight_type": "sequential",
    "enemies": [
      {"name": "homme-oiseau", "name_raw": "HOMME-OISEAU", "force": 11, "vie": 14},
      {"name": "faucon tueur", "name_raw": "FAUCON TUEUR", "force": 10, "vie": 7}
    ],
    "outcome": {
      "on_victory": "44",
      "on_defeat": "death",
      "on_flee": null
    }
  }
}
```
Omit the `fight` key entirely on pages with no combat.

---

## Part A — Choices (gains / losses)
- Preserve `text` and `file_path` unchanged.
- `choices` must have exactly one entry per number in `numbers`, in order — including numbers that are also combat outcomes (see Part B); combat is cross-referenced, not removed from `choices`.
- For each choice, infer `gains`/`losses` from the narrative text surrounding that branch point (patterns like "ôtez X pièces d'or", "rayez une ration", "ajoutez X points d'endurance", "perdez X points de vie", "gagnez", etc.). Amount defaults to 1 if not explicitly numeric.
- Each gain/loss entry carries both `element` (English key, lowercase, singular: `gold coin`, `ration`, `meal`, `lodging`, `endurance`, `life point`, …) and `label_fr` (the French label as used in the corpus, e.g. `pièce d'or`, `ration`, `repas`, `nuitée`). Keep the `element` → `label_fr` mapping consistent across the whole file: the same English key must always get the same French label.
- If no gain/loss pattern can be confidently matched, leave `gains`/`losses` as empty arrays.

## Part B — Combat encounters

Enemies appear as stat blocks:
```
HOMME-OISEAU FORCE: 11 VIE: 14
FAUCON TUEUR FORCE : 10 VIE : 7
```
i.e. `<ENEMY NAME (uppercase, possibly multi-word/hyphenated)> FORCE\s*:\s*<number> VIE\s*:\s*<number>`, repeated per enemy. Multiple enemies can appear on one page; combat is either **sequential** (defeat one, then the next) or **simultaneous** ("combattez-les simultanément", "en même temps", "les deux ennemis attaquent ensemble", …).

### Detection
For each page, scan `text` for:
1. The stat-block regex above (case-insensitive on labels; keep the enemy name as found in `name_raw`, normalized lowercase in `name`). This is the primary/most reliable signal.
2. Combat vocabulary as a fallback signal: `combattre`, `combat`, `vous défendre`, `affronter`, `engager le combat`, `se battre`, `attaque`, `tuer`, `blesser`, etc.

A page is flagged as a fight if either signal is present.

### Fields
- `fight_type`: `"single"` if one enemy; `"simultaneous"` when text explicitly indicates fighting together/at once; otherwise `"sequential"` (default for multiple enemies).
- `enemies`: one entry per stat block, in order of appearance (order matters for sequential fights); `force`/`vie` as integers. Empty array if only combat vocabulary was found without a stat block.
- `outcome.on_victory`: page to continue to once all enemies are defeated.
- `outcome.on_defeat`: `"death"` if text implies game over, otherwise a page number.
- `outcome.on_flee`: page number if fleeing is offered, otherwise `null`.
- Outcome pages should come from the page's `numbers`; resolve them from context (proximity to page-number references, keywords like "mort", "tué", "vaincu", "fuir", "fuite"). Leave any outcome that cannot be resolved as `null`.
- Keep `fight` separate from `choices` — combat resolution is dice/skill-based, not a player decision.

## Process
1. Read and parse the input JSON.
2. For each page:
   a. Split/parse the text around the embedded page-number markers to identify choice boundaries.
   b. Extract gains/losses per choice via pattern matching on common French phrasings in this corpus, attaching `element` + `label_fr` (Part A).
   c. Run stat-block regex + combat-vocabulary detection; if a fight is found, build the `fight` object (Part B).
3. Self-check: verify every `element` maps to exactly one `label_fr`, spot-check a sample of choices and fights against the raw text, and refine the patterns; repeat until extraction is stable.
4. Write `work/pages.json`.
5. Report a short summary: pages processed, choices extracted, choices with empty gains/losses, fights detected (by type), fights with unresolved outcomes or no stat block, and the final `element` → `label_fr` mapping.
